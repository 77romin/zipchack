# 대화 조건과 지도 추천 연결

사용자가 예산·조회 지역·계약월·주택 유형·생활 선호를 말하면 공식 전월세 조회 결과에서 후보를 추리고 대표 위치와 필요한 연령 자료를 자동으로 준비한다. 사이드바에서 동네를 하나씩 선택할 필요가 없다.

- 지역·월·유형은 명시적으로 수집한다. 통근시간만으로 임의의 조회 자치구를 정하지 않는다.
- 위치·연령 조회는 후보 최대20곳을 우선 준비한다. 성공 자료는 세션에서 재사용하며 실패 항목은60초 동안 반복 요청을 억제한다. 나머지 위치 미확인 후보는 번호 없이 남는다.
- 지도와 대화 답변은 동일한 `recommendation_rows` 결과를 사용한다. 대화에서 월세나 중요도를 바꾸면 같은 조회 범위의 저장 거래를 재필터링·재계산한다. 지역·월·유형 변경 시에는 다른 범위 자료를 조회한다.
- 파란 숫자: 기존 생활 선호 비교의 확인된 후보 순위. 주황색 `참고 n`: 공원·따릉이 원자료의 제외 기록이 있지만 선택 지표를 모두 계산할 수 있는 경우의 자료 내 참고 순위. 기존 엄격한 순위 필드는 유지한다.
- 회색 `후보`: 선호 미지정, 선택 지표 미확인, 거래 부분 조회 등으로 순위를 확정할 수 없는 경우. 위치 자체를 확인하지 못하면 핀도 표시하지 않는다. 점수 동률은 공동 순위다.
- 핀을 누르면 항목별 근거와 동네 통합 카드가 열린다. 개별 매물의 주소나 실제 통근 가능 여부를 뜻하지 않는다.
- 후보 자료가 바뀔 때 핀을 교체하고 화면을 맞춘다. 동일한 자료 갱신에는 지도 위치를 유지하며 후보가 사라지면 이전 핀도 제거한다.
- 입력 처리 중 지도 이벤트가 앱을 재실행해도 질문을 세션에 보관해 이어서 처리한다. 처리 실패도 대화에 남겨 안내가 사라지지 않게 한다.

현재 실시간 매물과 자동 경로시간은 제공하지 않는다. 공원 자료는 주요 공원 목록이고 시설 거리는 동네 대표점 기준의 직선거리다. 참고 순위를 전체 주거 적합도나 검증된 통근 순위로 해석하지 않는다.

## 대화 처리와 화면 갱신

대화 요청은 세션별 Future로 한 번 실행한다. API 조회 중 전체 화면이 다시 그려져도 같은 작업을 재사용하고, 완료 상태만 fragment에서 확인한다. 완료되면 대화·조건·거래·위치·연령 자료를 함께 반영한다. 초기화한 작업의 늦은 응답은 반영하지 않는다. API 키와 원본 예외는 화면이나 검증 결과에 저장하지 않는다.

처리 중 지도 범위 변경은 마지막 범위만 보관했다가 처리 후 반영한다. GMS의 502/503/504와 연결·시간 초과는 최대3회 시도하며 인증 오류·사용 한도는 재시도하지 않는다. 실패한 질문과 안내도 대화에 남긴다.

추천 점수와 카드의 시설 거리는 자동 확인한 동일 대표점을 사용한다. 위치를 확인한 후보에는 경계 평균점으로 계산한 다른 거리값을 섞지 않는다. 카드 패널은 지도 안에 고정 표시하며 닫을 수 있다. 지도 코드가 바뀌면 자산 해시로 프레임을 갱신하고 통계·조건만 바뀐 경우에는 기존 프레임을 유지한다.

## 실제 연결 검증 · 2026-10-23

- 수동 사이드바 조작 없이 대화로 중구·202609·오피스텔·보증금1000만원·월세70만원·공원 중요도5를 입력했다. 예산 내 과거 거래12건·6개 동네와 참고 순위6개 핀을 확인했다.
- 월세 상한60만원 변경 후 저장 거래를 재사용해3건·3개 동네로 줄었다. 광희동1가/오장동/황학동의 지도 번호와 대화 순서가 일치했다.
- 같은 예산에서 공원0·따릉이5로 바꾸자 광희동1가 점수가77점에서93.2점으로 변경됐다. 실제 데이터에서 세 동네의 순서는 같았으며, 순서가 뒤집히는 경우는 별도 테스트 자료로 검증했다.
- 추천 핀 클릭으로 광희동1가의93.2점, 최근접 대여소102m, 보증금500/월세45만원의 실제 과거 계약 예시와 출처를 확인했다.
- 초기 브라우저 동기 처리에서 재실행과 GMS502를 관찰했다. 비동기 처리·실패 안내 보존·제한 재시도 보완 후 위 후속 대화까지 확인했다.
- 전체 Python159개, 지도 브리지·추천 핀·대여소·초기 지도 JavaScript 테스트 통과.
