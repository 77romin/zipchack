# RAG 자료 준비와 벡터 색인

공식 공원 CSV의 132개 위치 레코드를 외부 문서로 변환한다. 본문에는 공원명·좌표·자료 한계를 기록하고 원문 URL과 데이터셋 기준일을 보존한다. 공원 자료만으로 동네의 도보 접근성·운영시간을 답할 수 없다.

공원 132건은 외부 자료다. 동네 메타데이터는 행정안전부 공식 목록의 서울 법정동 467개로 별도 구성했다. 초기 자체 설명 문서 5개를 연결했으며, 나머지 동네 문서 확장·P1/P2/P3·LangGraph·검색 및 답변 UI는 후속 단계다. 아직 추천 답변은 문서 RAG를 사용하지 않는다.

## 실행

```powershell
.\.venv\Scripts\python.exe scripts/prepare_neighborhoods.py
.\.venv\Scripts\python.exe scripts/index_rag.py --dry-run
.\.venv\Scripts\python.exe scripts/index_rag.py
```

`GMS_KEY`를 사용하며 기본 모델은 `text-embedding-3-small`이다. 모델을 바꾸려면 `.env`의 `RAG_EMBEDDING_MODEL`과 별도 `--db` 경로를 사용한다. 지원하지 않는 모델·권한·네트워크 오류는 실패로 표시한다. 실제 성공 여부와 개수는 실행 보고서로 확인한다.

두 컬렉션은 `zipchack_metadata`, `zipchack_external`이다. 로컬 저장소는 `storage/rag`이며 버전 관리에서 제외한다. 기본 색인 입력에 공원 132개·법정동 467개·위키 문서 5개를 함께 넣는다. 동네 item_id는 법정동 10자리 코드이며 기존 지도·주민등록 코드와 같은 값으로 연결한다.

`--items`로 UTF-8 JSONL 동네 자료를 추가할 수 있다. 필드는 item_id, document_id, title, text, source_url, observed_at, kind이며 kind는 metadata다. 임의 예시 동네를 실제 자료로 색인하지 않는다.

기본 청크는 1,000자·중복 200자이며 `--chunk-size`, `--overlap`으로 변경한다. 메타데이터는 항목 문서 전체를 하나로 유지한다. 항목·문서·유형·청크 위치로 ID를 만들고 본문·출처·설정의 해시로 변경 여부를 확인한다. 재실행 시 같은 청크는 재임베딩하지 않으며, 문서 축소 시 남은 오래된 청크를 제거한다. 원본 목록에서 아예 삭제한 문서는 자동 삭제하지 않는다. 별도 스냅샷 DB로 관리한다.

문서별 임베딩이 모두 성공한 후 갱신한다. 전체 색인은 문서 단위로 진행하므로 중간 실패 시 앞선 문서까지 저장될 수 있고 재실행으로 이어갈 수 있다. 다른 청크 설정은 동일 문서를 교체하므로 비교 실험은 반드시 서로 다른 DB 경로를 사용한다.

정량 검색·답변 성능은 아직 측정하지 않았다. 테스트용 고정 벡터는 저장 동작 검증에만 사용하고 실제 의미 검색 성능으로 보고하지 않는다.

## 2단계: 실제 동네와 자체 설명 문서

| 자료 | 범위 | 출처·한계 |
| --- | --- | --- |
| 동네 메타데이터 | 서울 25개 구, 현존 법정동 467개 | [행정안전부 공식 목록](https://www.code.go.kr/stdcode/regCodeL.do). 코드·전체 이름·자치구·존재 상태. 행정동이나 생활권 경계가 아니며 인구·가격·통근시간은 없음 |
| 자체 외부 문서 | 청운동·신당동·공덕동·연남동·역삼동 5개 | 한국어 위키백과. 서울·자치구·동네가 도입부에 일치하는 문서만 연결. 동음이의·다른 지역 문서 제외 |
| 기존 공원 | 132개 문서 | 서울 전체 주요 공원 위치. 가까운 공원을 법정동에 임의 귀속시키지 않음 |

공식 코드 전체 ZIP에서 CP949 TXT를 읽고 존재 상태·서울·동네 단계만 남긴다. 원본 해시·정규화 해시·확보 시점을 sidecar JSON에 저장한다. 100건 이상·25개 자치구·코드 중복 여부를 확인한다. Windows 줄바꿈과 무관하게 해시가 일치하도록 UTF-8 바이트로 저장한다.

위키백과는 MediaWiki API의 본문 전체 텍스트를 수집한다. 짧은 자체 문서도 제외하지 않는다. 현재 초기 5개는 직접 확인한 코드-제목 대응이며, LLM 후보 선별(P2)을 구현한 것으로 간주하지 않는다. 법정동 메타데이터 467개 확보와 467개 설명 문서 확보는 별개다. 문서가 없는 462개 동네에 주변 특성을 추측해 붙이지 않는다.

위키 텍스트는 각 문서의 판 링크(oldid), 판 번호, 판 시각, 기여자 이력 링크, CC BY-SA 4.0을 보존한다. [Wikimedia 이용약관](https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use)을 참조한다. 본문은 MediaWiki plaintext 변환 결과이며 링크·표·이미지의 모든 정보를 보존하는 것은 아니다. 원문에 오래된 내용이 포함될 수 있으므로 현재 운영·주거 적합성의 자동 검증으로 해석하지 않는다.

`WIKI_CONTACT`는 요청 User-Agent에만 사용하고 공유 데이터·보고서에는 넣지 않는다. 코드·제목·수집 방식별 캐시와 내용 해시를 보존한다. 정상 캐시 재실행 시 외부 호출 없이 재사용한다. 캐시가 없으면 연락처 설정 시 0.2초, 미설정 시 6.1초 간격을 두며 일시 오류는 최대 3회 재시도한다. 시간 초과·API 오류·지역 불일치는 실패이고 부분 결과로 기존 전체 문서 묶음을 덮어쓰지 않는다. `--refresh`는 공식 목록·위키 문서를 새로 수집한다.

벡터 저장 경로는 기본 `storage/rag`, 개별 외부 수집 캐시는 `storage/wiki`이며 둘 다 Git에서 제외한다. 공유되는 자료는 공개 데이터 스냅샷과 출처다. API 키·연락처·실제 사용자 대화는 포함하지 않는다.

## 유사도·MMR 검색 모듈

rag_retrieve.retrieve는 선택 동네 메타데이터를 항상 포함하고 해당 item_id의 외부 문서만 검색한다. k는 외부 청크 수이고 fetch_k는 두 방식의 공통 후보 수다. 현재 Chroma 기본 L2 거리로 후보를 가져온 뒤 cosine으로 정렬하며 MMR은 관련성과 선택된 청크와의 중복도를 함께 반영한다. 현재 기본 임베딩과 후보 검색 규칙을 비교 실험에서도 동일하게 고정해야 한다. 다른 동네와 서울 전체 공원 자료는 자동 혼합하지 않는다. 외부 문서가 없으면 메타데이터와 자료 부족 안내만 반환한다.

임베딩·벡터 조회·선별·전체 시간을 ms로 나눠 기록한다. 이 타이밍은 정식 성능 비교 결과가 아니다. 공덕동 실제 조회는 두 방식 모두 외부 청크 1개로 같은 결과이며 다양성 평가에 충분하지 않다. [실제 연결 기록](검증/RAG_검색_연결확인.json).

검색 모듈만 추가했으며 답변 생성·LangGraph·화면 연결·품질 평가·SVG 도표는 아직 후속 단계다.
