## 2. 요구사항에 맞춘 RAG 구현 범위

기준: [구현목표 정의서](구현목표_정의서.md), [원본 요구사항 참조](RAG_프로젝트_요구사항_참조.md). 원본의 지정 버전·두 컬렉션·항목 약 100건 이상·선택 항목 자체 문서 우선 포함을 확인하며 구현한다.

| 단계 | 구현 내용 | 완료 증거 |
| --- | --- | --- |
| 자료 준비 | 식별 가능한 동네 항목 약 100건 이상, 항목 자체 문서와 외부 공식 문서·출처·관련 항목·기준일 확보 | 원본 목록·출처/이용조건·데이터 스냅샷 |
| 색인 | 메타데이터와 외부 문서의 별도 Chroma 컬렉션, 청크 크기·중복 길이 설정, 임베딩·재색인 중복 방지 | 항목·문서·청크 수, 재실행 전후 개수, 임베딩 모델·소스 해시 |
| P1 | 선택 항목과 질문에서 검색어 추출. 자체 문서는 반드시 포함 | 파싱 가능한 출력·프롬프트 버전 |
| P2 | 외부 후보 문서 선별. 자체 문서 포함 규칙 우선, 검색어별 수집 캐시 | 선별/제외 근거·수집 기록 |
| 검색 | 선택 항목 메타데이터 항상 포함, 외부 청크 유사도/MMR 검색·병합·중복 제거 | 검색 청크 ID·문서 ID·점수·모드·설정 |
| LangGraph | 요구사항의 retrieve·generate 노드. P1·P2 수집 준비와 질의 흐름 구분 | 실제 컴파일 그래프·실행 추적·테스트 |
| P3 | 조회한 근거만 사용해 답변·주장별 인용, 근거 없으면 유보 | 원문과 대응하는 인용·없는 사실을 만들지 않는 테스트 |
| UI | 선택 동네별 대화와 근거, 검색 방식 선택, 자료 부족 안내 | 실제 브라우저 검증 |

## 3. 비교 실험의 세 조건

| 조건 | 검색 근거 | 비교 목적 |
| --- | --- | --- |
| A: RAG 미사용 | 문서 검색 근거 없음 | 검색 없이 답할 때의 기준 성능 |
| B: RAG + 유사도 | 동일 컬렉션·임베딩·Top-k의 유사도 검색 | RAG 효과 |
| C: RAG + MMR | 동일 자료·최종 근거 수, fetch_k·lambda 별도 기록 | 관련성과 다양성의 교환 관계 |

동일 질문·사용자 조건·생성 모델·모델 파라미터와 동일한 구조화 API 스냅샷을 사용한다. A에는 문서 검색을 제공하지 않지만 구조화 조회 결과는 B/C와 동일하게 제공해 검색 효과만 비교한다. A에 실제로 없는 인용을 요구하지 않는다. B/C는 최종 외부 근거 수·메타데이터 포함·중복 제거 규칙을 맞춘다. MMR이 항상 더 낫다는 전제를 두지 않는다.

## 4. 평가 질문과 정답 기준

- 요구사항 최소 대표 질문 5개 이상을 충족하고 본 실험은 30문항을 목표로 한다.
- 동네 특징·여러 근거 종합·비교·금액/시간/기준일·조건 변경·근거 없음 질문을 포함한다.
- 실험 전에 관련 문서/청크 ID, 필수 사실, 허용 가능한 유보, 조건 위반 기준을 라벨링한다. 검색 결과를 본 뒤 특정 방식에 유리하게 정답을 변경하지 않는다.
- 설정 조정용 질문과 최종 비교용 질문을 분리한다. 사람이 조건명을 가린 상태에서 정확성·근거 일치를 판정하고, LLM 평가는 보조로만 사용한다.

## 5. 지표와 분모

| 측정 대상 | 지표 | 정의·주의 |
| --- | --- | --- |
| 검색 관련성 | Precision@k·Recall@k | 사전 라벨된 관련 외부 청크/문서 기준. 청크와 문서 단위를 섞지 않음 |
| 검색 순서 | nDCG@k·MRR | 관련성 등급·첫 정답 순위 기준. 필수 메타데이터는 별도 집계 |
| 검색 다양성 | 고유 문서 수·청크 쌍 평균 코사인 유사도 | 다양성만 높다고 정확성이 높은 것은 아님 |
| 답변 정확성 | 필수 사실 충족률·잘못된 사실 비율 | 누락 사실과 무응답을 함께 보고 |
| 답변 근거 | 인용 정확성·주장-근거 일치·유보 적절성 | 검색 지표와 답변 지표를 구분. A의 검색/인용 일치 지표는 N/A |
| 서비스 조건 | 예산·지역·수단·시점 준수율 | 미확인 통근시간을 확정했다고 말하면 위반 |
| 성능 | 질의 임베딩·벡터 검색·MMR 선별·병합·생성·전체 시간 | perf_counter로 단계별 측정. 사용자 입력 대기·외부 지도 화면 시간은 제외 |
| 안정성 | 성공률·실패율·타임아웃 | 실패 사례를 빼고 평균만 보여주지 않음 |
| 비용 | 토큰·임베딩·수집/색인 시간 | 초기 준비 비용과 질의 실행 비용 분리 |

분모가 0이면 N/A다. 자료가 부족한 질문을 임의의 0점·100점으로 채우지 않는다. 질의 임베딩 시간을 포함한 전체 검색 시간과 벡터 연산 시간은 별도 집계한다.

## 6. 재현성·통계·산출물

- 질문당 조건별 3회 이상 반복을 기본으로 하고 warm/cold를 구분한다. 실행 순서를 순환/교차 배치한다. 소규모 표본의 p95는 불안정할 수 있으므로 표본 수와 원자료도 표시한다.
- 동일 질문끼리 정확도 차이와 응답시간 차이를 비교한다. 평균·중앙값·p95·표본 수·가능한 신뢰구간을 보고하며 유의성이나 일반적 우위를 과장하지 않는다.
- 원자료 JSONL에 question_id·item_id·condition·repeat·설정/모델/프롬프트 버전·스냅샷 해시·검색 ID·답변·인용·시간·오류를 저장한다. 인증키나 실제 개인 대화는 저장하지 않는다.
- 집계 CSV/Markdown 표와 독립적인 SVG 도표를 만든다. SVG는 막대/분포/쌍별 차이 등 측정 대상에 맞춰 구성하고 단위·축·조건·표본 수를 표시한다. 결과 미측정 상태를 예시 수치로 가리지 않는다.
- LangGraph 실제 노드·상태·조건 분기를 기준으로 UML 활동도와 시퀀스도를 작성한다. 편집 가능한 `.puml` 원본과 `.svg`를 함께 보관하고 구현이 바뀌면 같이 갱신한다.
- 실험 실행 명령·환경 버전·실패 로그·평가 라벨을 함께 보관해 같은 스냅샷으로 재현할 수 있게 한다.

현재 이 절은 실험 설계이며 RAG 구현·실험 결과·UML 완료를 뜻하지 않는다.
