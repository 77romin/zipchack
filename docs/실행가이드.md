# 집.착 실행 가이드

## 실행

프로젝트 폴더에서 다음 명령을 실행한다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

`.env.example`의 항목을 참고해 `.env`에 키를 입력한다. 실제 키는 커밋하지 않는다.
카카오맵 사용 설정을 켜고 JavaScript SDK 도메인에 실제 접속 주소(예: `http://localhost:8501`)를 등록한다.

## 현재 사용할 수 있는 기능

1. 직장·보증금·월세·탐색 반경·생활 선호를 입력하고 적용한다.
2. 직장을 검색하고 결과를 선택하면 지도에 직장 핀과 직선거리 반경이 표시된다.
3. 서울시 공식 따릉이 대여소 위치 CSV/XLSX를 업로드하면 반경 안의 대여소 핀·목록을 확인한다. 대여소 핀을 누르면 이름과 거리를 볼 수 있다. 실시간 재고는 사용하지 않는다.
4. 서울 열린데이터 키를 설정하고 공식 장소명/코드로 현재 상황을 조회한다. 인구 구성·주차장·지하철·전기차 충전·대기환경·상권의 6개 탭에서 세부 자료와 기준 시각을 확인한다. 누락값은 0 대신 미제공으로 표시한다.
5. 도시데이터 시설 지도 레이어에서 주차장·지하철·충전소를 선택한다. 유효 좌표만 표시하고 직장 선택 시 반경 안 시설만 남긴다. 시설 도트를 누르면 상세를 볼 수 있다.
6. 사이드바의 도시환경 비교 선호 설정에서 중요도·현재 인구 연령대·상권 활동 선호를 적용한다. 조회한 장소를 비교 목록에 추가하면 세션에서 최대 10곳을 비교한다. 같은 장소는 재추가 시 최신 조회로 교체하고, 데이터가 빠진 후보의 순위는 미확정으로 남긴다. 각 조회 시각과 화면의 점수 계산 기준을 함께 확인한다.

도시데이터의 조회 장소는 직장과 자동 연결되지 않는다. 제공되는 공식 장소 영역의 데이터이며 서울 전체 건물별 관측값이 아니다. 실시간 연령 구성은 거주민만의 연령 통계가 아니다.

따릉이 파일은 공식 제공 페이지에서 내려받는다: https://www.data.go.kr/data/15051893/fileData.do
허용 크기는 20MB다. 파일은 사용자 세션에서 읽고 프로젝트 폴더에 저장하지 않는다. 자료 기준일과 현재 운영 여부는 원본에서 확인한다.

## 아직 구현되지 않은 기능

매매 실거래가 수집·주거 후보 순위·공원과 주민등록 연령 통계·동네 경계별 색상·지도 연계 상담·Vector DB·문서 RAG·MMR·정량 실험은 후속 기능이다. 도시시설 색상 도트와 현재환경 비교는 구현했으며 예산을 포함한 주거 추천 순위는 아직 없다. 챗봇은 대화 조건 수집·수정·추가 질문을 지원한다. 제휴 API는 사용하지 않으며 경로는 카카오맵 길찾기 바로가기 방식으로 연결할 예정이다. 앱 내부 이동시간 계산은 제공하지 않는다.

## 테스트

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

테스트의 위치·XML 값은 명시적인 테스트 전용 데이터다. 서비스에서 실제 조회 실패를 샘플 데이터로 대체하지 않는다. Streamlit AppTest는 Python 화면 흐름을 확인하며 실제 브라우저 지도 타일·JavaScript SDK 동작을 검증하는 것은 아니다.

## 데이터 해석·검증

현재 인구 성별·연령과 소비 성별·연령은 서로 다른 표에 표시한다. 상주 비율을 거주민 전체 수로 바꾸거나 연령 비율과 곱하지 않는다. 주차 실시간 Y인 경우만 가능 면수를 표시하고 전기차 충전소의 이용 제한·상태를 별도로 확인한다. 상권은 신한카드 내국인 표본이다.

인증키 미설정과 네트워크·API 실패는 안내로 처리하며 샘플을 실제 응답으로 대체하지 않는다. 현재 서울 인증키 실조회는 미검증이며 공개 sample endpoint도 2026-10-22 실행 환경에서는 시간 초과로 실패했다. 실제 브라우저의 시설 도트·클릭 동작은 별도 확인이 필요하다.


## 대화로 조건 수집하기 (2026-10-22)

최종 화면은 대화를 중심으로 구성한다. 사용자가 조건을 말하면 AI가 명시한 값만 추출하고, 서버가 기존 조건과 합친 뒤 부족한 정보를 하나씩 질문한다. 기존 입력 화면은 개발 중 비교·확인용으로 유지한다.

- `.env`의 `GMS_KEY`를 사용한다. 모델은 기존 실습 설정인 `gpt-5.4-nano`이며 `GMS_MODEL`로 변경할 수 있다. 메시지를 전송할 때만 GMS에 요청하고 재시도로 자동 중복 호출하지 않는다.
- 직장, 거래 유형, 예산(만원), 편도 통근시간·수단, 희망 주민 연령대와 생활 선호를 세션에 누적한다. “월세만 60으로” 같은 수정은 다른 조건을 유지한다. 거래 유형을 바꾸면 이전 계약 유형의 예산은 다시 확인한다.
- 필수 조건은 직장·거래 유형·해당 예산·통근수단·최대 편도 시간이다. 관리비는 월세에 포함하지 않는다. 숫자·형식 오류나 AI 연결 실패가 나면 기존 조건은 보존한다.
- 현재 월세 조건이 모이면 기존 직장 검색·지도 조건에 연결한다. 탐색 반경 3km는 임시 직선거리 표시값으로, 사용자가 말한 통근시간으로 계산한 범위가 아니다. 직장 위치는 검색 결과에서 직접 확인한다. 전세·매매는 대화 조건 수집만 지원한다.
- 현재환경 비교 슬라이더와 대화 조건은 아직 자동 통합하지 않았다. 향후 추천 단계에서 검증된 구조화 조건을 공통 입력으로 사용할 예정이다.
- 아직 실제 거주 추천·문서 RAG는 미구현이다. 전월세 실거래 조회는 아래 별도 절을 따른다. 조건이 모여도 근거 없는 추천지나 통근시간을 생성하지 않는다. 최종 흐름은 **조건 수집 → 부족 정보 확인 → 데이터 검색·필터·점수 계산 → 근거와 함께 추천 → 대화로 재조정**이다.
- 대화 원문은 GMS로 전달되며 직장·예산 등이 포함될 수 있다. 최근 12개 메시지와 누적 조건만 전송하고, 화면 대화는 최대 40개 메시지까지 세션에 보관한다. 파일·Vector DB에 대화 기록을 자동 저장하지 않는다.


## 전월세 실거래 조회 (2026-10-22)

아파트·연립다세대·단독다가구·오피스텔 공식 API를 연결했다. 조회 구와 계약월·유형을 선택하고 조회 버튼을 누른다. 데이터는 세션에 보관되며 대화의 보증금·월세 조건을 바꾸면 추가 호출 없이 필터를 다시 적용한다. 전세는 월세가 0인 거래만 선택한다. 매매는 후속 단계다.

각 서비스 상세에서 확인한 일반 인증키(Decoding 권장)를 `.env`의 `DATA_GO_KR_APT_RENT_KEY`(아파트), `DATA_GO_KR_RH_RENT_KEY`(연립다세대), `DATA_GO_KR_SH_RENT_KEY`(단독다가구), `DATA_GO_KR_OFFI_RENT_KEY`(오피스텔)에 각각 입력한다. 유형별 키를 우선 사용하며, 공통으로 쓸 수 있는 키가 있을 때만 `DATA_GO_KR_SERVICE_KEY`를 대체값으로 사용한다. 누락된 유형은 미조회로 표시하고 다른 유형은 계속 조회한다. Encoding 키도 한 번 디코딩해 요청하므로 이중 인코딩을 피한다. 키 입력 외에도 사용할 유형별 활용신청·승인이 필요하다.

| 주택 유형 | 공식 신청·명세 |
| --- | --- |
| 아파트 | https://www.data.go.kr/data/15126474/openapi.do |
| 연립다세대 | https://www.data.go.kr/data/15126473/openapi.do |
| 단독다가구 | https://www.data.go.kr/data/15126472/openapi.do |
| 오피스텔 | https://www.data.go.kr/data/15126475/openapi.do |

금액은 만원이다. 결측 금액을 0으로 바꾸지 않으며 보증금·월세가 확인된 거래만 필터에 사용한다. 단독다가구의 면적은 연면적이므로 다른 유형의 전용면적과 구별한다. 같은 조건의 거래도 서로 다른 계약일 수 있어 임의로 중복 제거하지 않는다. 최신 계약일 순으로 보여주며 통근·공원·연령 조건까지 검증한 순위는 아니다.

유형당 최대 5페이지, 페이지당 요청 1000건으로 제한한다. 일부 유형 실패나 조회 상한·형식 오류 제외 건수를 표시한다. 조회 실패를 거래 0건이나 샘플 결과로 바꾸지 않는다. 현재 거래 기록 조회는 수동 범위 지정이며, 대화에서 자동으로 동네 후보를 탐색하는 기능·Vector DB·RAG는 후속 단계다. 현재 매물과 계약 가능 여부를 뜻하지 않는다.


## 예산 기준 동네 후보와 대화 연결 (2026-10-22)

실거래를 한 번 조회한 뒤 대화에 “추천해줘”라고 입력하면, 현재 대화 예산에 맞는 거래를 법정동별로 묶어 최대 5곳을 안내한다. 예산 변경 후 다시 요청하면 저장한 거래에 새 조건을 적용하고 추가 실거래 API 호출은 하지 않는다. 화면에서도 같은 규칙의 동네별 건수와 선택한 동네의 거래를 볼 수 있다.

후보의 순서는 예산에 맞는 조회 거래 건수 내림차순이며 동률은 동네명 순이다. 거래량을 주거 적합도 점수나 현재 매물 수로 해석하지 않는다. 각 예시는 동일 계약의 보증금·월세·유형·계약일·공식 출처를 함께 표시한다. 조회 범위·시각·일부 실패 또는 제외 여부를 표시하고, 0건이어도 조건을 임의로 완화하지 않는다. 공원·따릉이·거주민 연령·통근시간 조건은 보존하지만 이 단계에서는 검증하지 않는다.

대화 답변은 검증된 구조화 조회 결과에서 서버가 작성한다. 아직 문서 검색·생성 RAG 답변은 아니며 자동 지역 탐색·종합 추천 순위는 후속 단계다. 동네 대표점 지도 연결은 아래 절을 따른다.


## 동네 후보 지도 연결 (2026-10-22)

실거래 조회 후 ‘거래를 살펴볼 동네’에서 동네를 고르고 ‘선택 동네 지도에 표시’를 누른다. 카카오 주소 검색의 REGION 결과 중 조회 구·법정동이 정확히 일치하는 대표 좌표만 사용한다. 좌표는 세션에서 동네별로 재사용한다. 실패·불일치·복수 좌표는 지도에 대체 위치를 표시하지 않는다.

지도 위 주황색 이름표는 동네 대표점이다. 개별 주택·거래 건물의 좌표나 동네 경계가 아니다. 표식 클릭 시 계약월과 예산에 맞는 조회 거래 건수를 확인한다. 직장 위치를 선택했다면 직장과 동네가 함께 보이도록 지도 범위를 맞춘다. 이는 실제 통근시간 검증이 아니다. 거래 표는 같은 동네 선택으로 필터된다. ‘전체’를 고르거나 예산에 맞는 후보가 없어지면 동네 표식도 사라진다.

추가 키는 필요 없으며 기존 `KAKAO_REST_API_KEY`로 위치 조회, `KAKAO_JAVASCRIPT_KEY`로 지도 표시를 한다. 공식 좌표 응답 명세: https://developers.kakao.com/docs/ko/local/dev-guide#address-coord


## 동네 생활환경 확인 (2026-10-22)

후보 동네를 지도에 표시하면 대표점 기준 300·500·1000·1500m 안의 공원과 따릉이 위치를 확인한다. 공원은 서울 주요 공원 API 또는 좌표가 포함된 공식 CSV/XLSX, 따릉이는 기존 공식 위치 파일을 사용한다. 위도·경도 없는 파일은 임의 변환하지 않는다. 출처·불러온 시각·제외 행을 표시하며, 자료가 없으면 미확인으로 남긴다. 반경 0건도 실제 시설 부재를 보장하지 않는다. 동네 전체·개별 집의 보행 접근성을 뜻하지 않으며 아직 종합 추천 점수에는 넣지 않는다.

법정동별 주민등록 연령은 별도 공식 API를 연결했다. https://www.data.go.kr/data/15108074/openapi.do 에서 활용신청하고 해당 서비스의 Decoding 키를 `.env`의 `MOIS_RESIDENT_API_KEY`에 입력한다. 기존 전월세 키를 임의로 재사용하지 않는다. 법정동 코드·기준월을 일치시켜 단일 법정동(lv=7)·거주자(regSeCd=2)를 조회한다. 총인구와 성/연령 합계를 검증한 뒤 희망 연령대 비율을 계산한다. 등록 거주자 기준이며 외국인은 제외된다. 실시간 인구나 실제 현재 거주자의 전수 조사와 구별한다. 키 미설정·응답 실패·코드 미확인 시 연령 비율은 미확인이다.

## 예산 후보의 생활 선호 비교 (2026-10-22)

예산에 맞는 거래가 있는 동네 중 위치를 확인한 후보를 공원·따릉이·주민등록 연령 선호로 비교한다. 대화에서 중요도를 바꾸면 같은 자료에 조건을 다시 적용하며 새 API 호출은 하지 않는다. 아직 위치를 확인하지 않은 후보도 표에서 제외하지 않고 미확인으로 남긴다. 주민등록은 화면에서 선택한 같은 기준월만 비교한다.

공원·따릉이 점수는 대표점과 자료 내 최근접 좌표 사이 직선거리 d(m)에 대해 max(0,1-d/1500)×100이다. 주변 시설 목록의 반경을 바꿔도 점수 기준 1500m는 바뀌지 않는다. 연령은 희망 주민등록 거주자 연령대 비율(%)이다. 중요도 1~5로 가중 평균하고 0은 제외한다. 연령대 선호가 있고 연령 중요도가 없다면 공개된 기본값 3을 사용한다. 불연속 연령대는 선택 구간만 합산하고 0명 지역의 비율은 미확인이다.

빠진 항목은 0점으로 채우지 않는다. 알려진 항목의 참고 점수와 가중 근거 확인율을 표시하고, 선택 지표·원본 제외 기록·실거래 범위의 제한이 있으면 순위를 미확정으로 남긴다. 동률은 공동 순위다. 확인율은 정확도나 데이터 완전성의 확률이 아니다. 주요 공원 목록과 업로드 파일의 공간·시점 한계는 유지된다. 아직 연결되지 않은 선호 지표도 임의의 점수를 주지 않는다.

대화에서 “추천해줘”라고 하면 예산 거래 근거에 생활 선호 비교와 출처를 덧붙인다. 실제 통근시간·현재 매물·개별 집의 종합 적합도는 검증하지 않았으며, 이는 문서 RAG 답변이 아닌 구조화 자료 기반 계산이다.
