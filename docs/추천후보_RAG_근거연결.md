# 추천 후보 RAG 근거 연결

RAG 활용을 켜고 조건을 입력하면 추천 계산 결과 중 위치·법정동 코드가 확인된 최상위 후보를 근거 검색 대상으로 사용한다. 지도에 기본 선택된 동네와 추천 후보가 달라 생기던 검색 대상 불일치를 해결했다. 현재는 상위 후보 한 곳의 설명이며 전체 후보를 LLM으로 재평가하는 기능은 아니다.

## 문서 준비

- 공식 법정동 메타데이터와 해당 코드에 연결된 기존 위키백과 스냅샷을 준비한다.
- 추천 계산에 사용한 동일 대표점의 500m 직선거리 내 따릉이·주요 공원 목록을 각각 외부 문서로 변환한다. 데이터 출처 URL과 실제 자료 기준일을 보존한다.
- 동일 법정동 코드·기준월로 확인한 주민등록 자료가 있을 때만 연령 문서를 추가한다. 미조회 인구를 0명으로 만들지 않는다.
- 문서 내용의 SHA256별로 `storage/rag_candidates/`에 별도 Chroma 색인을 만든다. 메타데이터·외부 컬렉션을 분리하고 변경 없는 문서는 재임베딩하지 않는다. 사용자 직장·예산·대화 원문은 문서에 저장하지 않는다.
- 준비 후 기존 LangGraph의 retrieve → generate와 선택한 similarity/MMR 설정을 실행한다. 근거 준비 실패 시 조건 추천 결과는 보존하고 실패 안내를 표시한다.

후보가 없으면 기존 지도 선택 동네의 저장 색인을 검색한다. RAG를 끄면 문서 준비·임베딩·근거 답변을 실행하지 않는다. 자료 묶음별 색인은 로컬에 누적되며 자동 정리 정책은 아직 없다.

## 해석 범위

위치 목록은 현재 자전거 재고·개별 주택 도보거리·실제 통근시간을 제공하지 않는다. 주요 공원 자료는 전체 공원 전수목록이 아니므로 목록 내 0곳을 주변 공원 부재로 해석하지 않는다. 주민등록 인구는 생활인구와 구분한다. 가격 답변용 실거래 문서 준비와 P1/P2 외부 문서 자동 확장은 아직 이 대화 흐름에 연결하지 않았다. 기존 수동 준비 CLI는 유지한다.

## 검증

2026-10-23 전체 Python 테스트 161개 통과. 추가 회귀 검증은 추천 후보와 지도 선택 동네가 다를 때 검색 대상, 반경 밖 시설 제외, 출처·기준일 보존, 잘못 연결된 인구 제외를 확인한다.

실제 GMS 연결은 테스트 대표점(신당동 37.565, 127.014)에서 수행했다. 문서 4개를 준비하고 유사도 검색에서 5개 청크를 새 임베딩했다. 같은 자료의 MMR 검색은 새 임베딩 0개였으며 두 방식 모두 retrieve → generate 및 출처 인용 답변을 반환했다. 이는 단일 연결 확인이며 정확도·속도 우열의 근거가 아니다. [연결 결과](검증/추천후보_RAG_연결결과.json)에 답변·인용·실측 시간을 기록했다.

다음 단계는 동일 질문셋·정답 근거를 고정한 유사도/MMR 및 RAG 전후 평가, SVG 도표·표와 LangGraph UML 산출물이다.
